# ☕ Telegram Shop — бот + Mini App + оплата

[![CI](https://github.com/trapeezzy/telegram-shop-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/trapeezzy/telegram-shop-bot/actions/workflows/ci.yml)

Интернет-магазин внутри Telegram: витрина в виде Mini App (веб-приложение прямо в мессенджере),
оплата картой через Telegram Payments, заказы со статусами и админ-панель в боте.
Покупатель не уходит из Telegram, а владелец магазина управляет товарами и заказами с телефона.

Демо-тема — обжарочная кофе, но каталог, тексты и настройки меняются под любой магазин.

## Возможности

**Витрина (Mini App)**
- Каталог с категориями, поиском и карточками товаров, бейдж «Осталось N шт.»
- Корзина синхронизируется между устройствами (Telegram CloudStorage)
- Расчёт доставки и подсказка «добавьте ещё на N ₽ — доставка бесплатно» с прогресс-баром
- Оформление: курьер или самовывоз, данные покупателя запоминаются
- Нативный интерфейс Telegram: MainButton, BackButton, виброотклик, цвета под светлую и тёмную тему
- Без сборщиков и фреймворков — чистый HTML/CSS/JS, который раздаёт бэкенд

**Оплата**
- Telegram Payments (ЮKassa, Stripe и другие провайдеры из @BotFather) — счёт с позициями заказа
- Перед списанием денег бот проверяет, что заказ ещё актуален и товар есть на складе
- Неоплаченный заказ можно оплатить позже из чата; через 30 минут он отменяется автоматически
- Демо-режим без провайдера: весь путь заказа работает без реальных денег

**Бот**
- «Мои заказы» со статусами и уведомления при каждом изменении: оплачен → передан курьеру / готов к выдаче → выполнен
- Кнопка «Магазин» в меню чата открывает витрину в одно касание

**Админ-панель** (`/admin`)
- Карточка нового заказа приходит сразу после оплаты — со ссылкой на покупателя и кнопками смены статуса
- Товары: добавление с фото прямо в чате, цена, остаток, скрытие с витрины
- Статистика за 30 дней: выручка, средний чек, топ товаров
- Выгрузка заказов в CSV, которая сразу открывается в Excel

## Как проходит оплата

```
Mini App ──POST /api/orders──▶ API: проверяет подпись initData, считает сумму по ценам из БД,
                               создаёт заказ «ждёт оплаты» и счёт (createInvoiceLink)
Mini App ──openInvoice──▶ Telegram: форма оплаты
Telegram ──pre_checkout_query──▶ бот: заказ не отменён? сумма та же? товар есть?  → ok / отказ с причиной
Telegram ──successful_payment──▶ бот: атомарно списывает остатки, статус «оплачен»,
                                      чек покупателю, карточка заказа админу
```

## Запуск

### Сервер (Docker + HTTPS)

Telegram открывает Mini App только по HTTPS. Caddy в составе `docker compose` сам получает
сертификат Let's Encrypt — нужен лишь домен, направленный на сервер.

```bash
git clone https://github.com/trapeezzy/telegram-shop-bot.git
cd telegram-shop-bot
cp .env.example .env      # BOT_TOKEN, ADMIN_IDS, DOMAIN (и PAYMENT_PROVIDER_TOKEN для оплаты)
docker compose up -d --build
```

### Локально

```bash
python -m venv .venv
.venv\Scripts\activate           # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
python -m app
```

Витрина откроется в браузере на http://localhost:8080 в режиме предпросмотра (без оформления заказа).
Чтобы открыть её в Telegram, нужен публичный HTTPS-адрес — проще всего туннель
[cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/):

```bash
cloudflared tunnel --url http://localhost:8080
```

Полученный адрес `https://….trycloudflare.com` укажите в `WEBAPP_URL` и перезапустите бота.

### Тестовая оплата

1. @BotFather → ваш бот → **Payments** → выберите провайдера, например «ЮKassa: тест».
2. Токен вида `381764678:TEST:…` — в `PAYMENT_PROVIDER_TOKEN`.
3. Платите тестовой картой провайдера (у ЮKassa: `5555 5555 5555 4477`, любой срок и CVC).

Пока токен не задан, работает демо-оплата: заказ оплачивается кнопкой без списания денег.

### Тесты

```bash
pytest
```

52 теста: правила заказов (суммы, доставка, остатки, статусы), подпись initData (подмена
пользователя, чужой бот, просроченная подпись), API (цены из запроса игнорируются, чужой заказ не
оплатить), сквозные сценарии бота через настоящий `Dispatcher` (pre_checkout, повторное уведомление
об оплате, смена статусов, админка, автоотмена) и совпадение миграций с моделями.

## Настройки

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather |
| `ADMIN_IDS` | — | Telegram ID администраторов через запятую |
| `WEBAPP_URL` | `http://localhost:8080` | публичный HTTPS-адрес витрины |
| `PAYMENT_PROVIDER_TOKEN` | — | токен провайдера; пусто — демо-оплата |
| `CURRENCY` | `RUB` | валюта счетов |
| `DELIVERY_PRICE` / `FREE_DELIVERY_FROM` | `300` / `3000` | доставка и порог бесплатной доставки, ₽ |
| `ORDER_TTL_MINUTES` | `30` | через сколько отменяется неоплаченный заказ |
| `SHOP_NAME`, `PICKUP_ADDRESS`, `SUPPORT_CONTACT` | — | данные магазина |
| `DATABASE_URL` | `sqlite+aiosqlite:///shop.db` | строка подключения SQLAlchemy |
| `REDIS_URL` | — | Redis для состояний диалогов |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс для дат в сообщениях |
| `DOMAIN` | — | домен для HTTPS в docker compose |

## Технические решения

- **Сервер не доверяет клиенту.** Mini App присылает только id товаров и количество — цены, доставку и
  итог сервер считает сам. Покупатель определяется по подписи `initData` (HMAC от токена бота) с
  ограниченным сроком жизни, поэтому подменить пользователя или заказ через прямой вызов API нельзя.
- **Деньги — целые копейки.** Как в Telegram Payments; никаких ошибок округления float.
- **Остатки списываются в момент оплаты, атомарно** (`UPDATE … WHERE stock >= qty`). Если последний
  товар купили параллельно, заказ всё равно засчитывается (деньги уже получены) и помечается для админа.
- **Идемпотентность оплаты.** Повторный `successful_payment` не списывает товар второй раз.
- **Нет дублей заказов.** Если покупатель закрыл окно оплаты и нажал «Оплатить» снова, открывается тот же счёт.
- **Платёж не теряется.** Антифлуд пропускает `successful_payment` всегда, а оплата заказа, отменённого
  по таймауту секундой раньше, всё равно его засчитывает.
- **Одна бизнес-логика на всех.** Бот, API и платёжные хендлеры вызывают `services/orders.py` —
  правила описаны в одном месте и покрыты тестами.
- **Фото без файлового хранилища.** Админ загружает фото в бота, в БД хранится `file_id`, API один раз
  скачивает файл из Telegram и отдаёт с кэшем; новый файл — новый URL.
